# Phase 03 — Decisions

| # | Decision | Rationale / trade-off |
| --- | --- | --- |
| D1 | Two shells selected at ONE declaration point (`router.tsx` route groups); AppShell retired (git-rm'd); `design.literals` allowlist trimmed to 1 entry | FR-01's "no surface renders both shells" enforced structurally, not by review. The 404 catch-all deliberately stays inside StaffShell (skip link + main survive unknown paths). |
| D2 | Toast host is `role="region" aria-label="Notifications" aria-live="polite"` — NOT `role="status"` | An always-present status collides with every surface's strict `getByRole('status')` success lookups (Q3 keeps inline text). The region announces inserted toasts via aria-live without occupying the status role. Unit-pinned in structure.test.tsx. |
| D3 | Shortcut tiles use `aria-label`s from a `SHORTCUT_ARIA` map; visible text `aria-hidden` | Accessible-name matching is case-insensitive SUBSTRING (cost several convergence rounds): tile text like "Sessions" would collide with the nav link "Sessions". Descriptions share NO word with nav labels. |
| D4 | Switcher labels "Viewing — Where" / "Viewing — Scope" (ids `context-restaurant`/`context-branch`) | Same substring law: NO shell-level label may contain "Restaurant"/"Branch" — six+ suites target page selects by those names. |
| D5 | CustomerShell grows a session bar (sign-out button) for signed-in visitors | The 020 walkthrough pins "Sign out" on `/account/password`; removing it broke a shipped surface (F3 regression). It is an account action, not navigation — FR-01's zero-nav contract holds. No unit pins existed for CustomerShell. |
| D6 | Cross-file `fionaLock` (atomic mkdir under test-results/, stale-steal 10 min, bounded wait) instead of global worker caps | fullyParallel stays for everything else (the suite's speed is part of the gate); only the genuinely shared fixture (Fiona) is serialized, at three granularities: sign-in (brief), walkthrough (poisoned window), journey (ownership span). |
| D7 | Reports' customer rounds moved T3→T2; void flow scoped by `data-round-id` | T3 is the seeded free table used by four suites; per-round id scoping (bill.void.audit's existing pattern) makes each suite own its card regardless of residue. |
| D8 | `test:integration` serialized (`--no-file-parallelism`) rather than making provisioning's cleanup mid-suite | The provisioning suite's design (live membership for the span, proving the one-time credential works) is correct; auth.signin's exact-set assertion is correct; they only conflict concurrently. Serializing files costs ~30s at the gate and is structural. |
| D9 | Platform onboarding uses a per-run owner email | The RPC's linked-identity branch is legitimate behavior; the credential assertions need the minting branch deterministically. Unique-per-run keeps reruns valid against a shared DB. |
| D10 | New `e2e/shell.test.ts` carries the shell CONTRACT (11 tests) instead of scattering chrome assertions | The two-shells rule, one-main-per-shell, persona nav matrix, drawer, context persistence, dialog close, offline Retry, and sign-out are chrome-level contracts — one file, pinned names, first-run green. |
| D11 | verify ordering discipline: verify runs before a full E2E pass (or after `db:reset`) | E2E residue (journey tenant by plan D1) intentionally breaks exact-seed DB assertions; the gate order in docs/development.md step 9 already implies this — now recorded with evidence. |
