## Master Plan phase-9 contract (condensed)
- **Purpose**: the cashier's shift console — live round queues, reliable transitions, order modifications, voids with reasons, session oversight and closure, a readable bill — realtime that never lies about state.
- **Scope**: `/dashboard/rounds` (queue grouped by state, per-round actions, line modification, void, bill panel, session linkage); `/dashboard/sessions` + branch session panel (open sessions, participants, close with confirmation); operational alerts + new-round cue presentation; the bill/aggregated view (subtotal, items, extras, tax lines, grand total, voided section, participants, delivery address echo); realtime refresh behavior + freshness affordances.
- **Out of scope**: NO payment capture, bill splitting, printing, accounting (§3.8 C4). No change to transition legality, void overlay semantics, bill's non-voided summing rule, RPC authorization, audit writing. No manual "add round" surface.
- **Existing contracts**: `get_branch_rounds`, `get_kitchen_queue` (money-free), `accept_round`, `start_preparation`, `mark_round_ready`, `lock_round`, `mark_out_for_delivery`, `mark_completed`, `modify_round_line` (captured-price re-derivation), `void_round` (reason ≤ 500; boundaries: dine-in@lock, delivery@out_for_delivery+, takeaway@ready; one generic refusal), `get_session_bill` (non-voided grand total), `get_branch_open_sessions`, `close_session`, realtime tables `rounds`/`kitchen_tickets`, 200 ms coalescing + `SUBSCRIBED` recovery, `useNewRoundCue`, actor attribution.
- **Key FRs**: FR-01 queue grouped by state with counts + per-group empty states; FR-02 per-round actions exactly per state machine, busy/disabled, no double-submit; FR-03 line modification (remove/reduce) with consequence messaging + verbatim refusals; FR-04 void flow with mandatory reason, boundary-aware, voided distinct from lock; FR-05 bill panel (participants, line detail, tax lines, voided section, grand total as returned); FR-06 session oversight list + confirmed closure; FR-07 realtime freshness (visible "last updated"/pulse, coalesced refetch, recovery after reconnect); FR-08 new-round cue as announcement with a clear path to the new round; FR-09 refusal routing to the originating card, verbatim; FR-10 long-queue performance (virtualization only if measured).
- **UX/Visual**: "what needs me now?" first; one deliberate tap; confirmation for destructive; moved cards visibly leave groups; busy queue never blocks on one card; money never on kitchen-blind surfaces. Card/board language, state vocabulary (color+label+icon), tablet-at-arm's-length density, tabular money alignment, distinct voided styling, bill reads like a printed check.
- **Responsive**: primary tablet landscape + desktop; mobile read/alert-capable with key transitions (documented secondary); columns collapse to stacked groups on narrow widths.
- **A11y**: action names preserved (`Accept round`, `Start preparation`, `Mark ready`, `Send out for delivery`, `Mark completed` + modify/void controls); groups as labelled regions/lists; polite live regions; `data-round-state`/`data-round-id` preserved; focus never stolen by refetch; confirmations trap+restore focus.
- **Testing**: unit — staffops.client payload discipline preserved (money-free parser keeps rejecting money keys), refusal routing + state grouping mapping; E2E — kitchen.cashier, bill.void.audit, session.surfaces, realtime assertions preserved; NEW tablet-viewport pass, keyboard-only transition path, reconnecting banner.
