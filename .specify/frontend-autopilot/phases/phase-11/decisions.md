# Phase 11 — Decisions (specs/031 D1–D6, with implementation notes)

- **D1 — Cutoff pre-emption: disabled ADD affordance only; server authority intact.** `cutoffCrossed` derives from the shared `useSessionRounds` cache (the 10 s poll is the client's knowledge); pending/errored → open (no speculative closing). 'Add to cart' becomes a real `disabled` with `aria-describedby="cutoff-notice"`; the notice gains the crossed sentence + a polite announcement paragraph (aria-live town-crier enters DOM with the state, never role="status"). The submit path and the cart stay alive — the crossover race belongs to the server, whose refusal renders verbatim.
- **D1-parity (decided during implementation, supersedes the original F4 draft).** The server's `submit_round` EXISTS clause (migrations/20260920160000_channel_schema.sql) reads EVERY round of the session — voided included; the customer rounds payload carries no voided flag. The mirror therefore checks all rounds too (voided rounds COUNT). Server parity is the contract; the dangerous lie is the UI claiming CLOSED when the server would accept — or open when it will refuse. Mirroring exactly keeps both directions honest. F4's checklist row was rewritten accordingly; the migration reference is recorded.
- **D2 — The channel filter ships.** Native radio fieldset (`data-testid="channel-filter"`) above the board; `matchesChannel` pure predicate (unit-tested, incl. the no-silent-widening case); page-level useState; default 'All channels' renders the exact frozen board. No persistence, no URL state.
- **D3 — Completion two-step; dispatch one-tap.** 'Mark completed' (pinned name) opens CompletionConfirmDialog (ConfirmDialog composition; confirm 'Complete the delivery', cancel 'Not yet', busy-aware; the bound address restated inside as a courtesy). Dialog errors stay OFF — refusals route to the card's refusal slot as everywhere else. Dispatch unchanged (recoverable by contract; the four-transition journey clicks it directly).
- **D4 — Takeaway pickup highlight built on `ready`.** StatusTimeline milestone emphasis (static pill — no motion); polite 'Your pickup order is ready.' announcement in RoundsHistory when the payload shows any `ready` (delivery gets 'On its way' emphasis; dine-in renders neither timeline nor announcement).
- **D5 — Sessions list: neutral 'Counter session' marker.** `table_label ?? 'Counter session'` with the §3.8 conflict recorded in code comment + ledger; NO channel claim (the read payload has no session_type; adding it is a backend change this phase may not make).
- **D6 — Kitchen has zero code changes; blindness is proven by test.** channel.operations walks a REAL delivery round through the kitchen board and asserts address-absence ('9 Channel Road' substrings, 'Deliver to') and the channel-neutral 'Counter order' head over the live round.
- **Component reuse thrifting.** DispatchActions merged into the existing pinned TransitionActions (the pinned names ARE the contract; a new wrapper would fork it). AddressEcho not extracted — the three existing address lines (indicator echo, round card, bill) already render in their own treatments; extraction would move markup for zero pin value.
- **E2E migration (D1, recorded).** session.surfaces' FR-011 journey: the second add moved BEFORE the dispatch transition (below the cutoff) with a same-place visibility assertion; the four staff transitions, the verbatim refusal, and the preserved cart are untouched. The disabled-affordance assertions live in the NEW channel.operations spec (they belong to the phase under test).
